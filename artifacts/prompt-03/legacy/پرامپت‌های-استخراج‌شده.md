# پرامپت: پلیر ویدیویی + صوتی درس‌ها با حافظه‌ی پیشرفت و سینک سرور

## هدف
برای هر درس، از هر کتاب پایه نهم، دو پلیر اضافه شود:
1. **پلیر ویدیویی** برای فایل آموزشی MP4 همان درس.
2. **پلیر صوتی** برای فایل آموزشی MP3 همان درس (مثلاً پادکست/توضیح صوتی معلم).

هر دو پلیر باید «حافظه‌دار» باشند و وضعیت‌شان با سرور Appwrite سینک شود (چند دستگاه = یک وضعیت پیشرفت).

## کنترل‌های موردنیاز (هر دو پلیر)
- پخش/مکث، عقب/جلو ۱۰ ثانیه، عقب/جلو یک "نشانه‌ی فصل" (chapter marker در صورت وجود)
- کنترل سرعت پخش: 0.75x / 1x / 1.25x / 1.5x / 2x
- نوار پیشرفت قابل درگ (Seek Bar) با نمایش زمان فعلی/کل
- دکمه‌ی "ادامه از همان‌جا" هنگام بازگشایی مجدد درس
- حالت پس‌زمینه برای صوت (Media Session / Notification Controls اندروید)

## مدل داده (Appwrite Collection: `lesson_media_progress`)
```json
{
  "userId": "string",
  "bookCode": "string",     // مثلا C905
  "lessonId": "string",
  "mediaType": "video|audio",
  "lastPositionSec": "number",
  "durationSec": "number",
  "playbackSpeed": "number",
  "isCompleted": "boolean",
  "viewCount": "number",
  "viewHistory": [
    { "date": "ISO8601", "speed": "number", "fromSec": "number", "toSec": "number", "isReplay": "boolean" }
  ],
  "seekJumps": [
    { "atClientTime": "ISO8601", "fromSec": "number", "toSec": "number", "direction": "forward|backward" }
  ],
  "updatedAt": "ISO8601"
}
```

## رفتار مورد انتظار
- هر بار کاربر پلیر را باز می‌کند: از سرور `lastPositionSec` و `playbackSpeed` خوانده شود و پخش از همان‌جا (و همان سرعت) شروع شود.
- هر ۵ ثانیه یا هنگام مکث/خروج/تغییر سرعت/seek: یک رویداد آپدیت به سرور بفرستد (debounce، نه هر فریم).
- هر seek بزرگ‌تر از ۳ ثانیه به‌عنوان یک آیتم در `seekJumps` ثبت شود.
- وقتی کاربر ویدیو/صوت را تا انتها یا بالای ۹۰٪ ببیند → `isCompleted = true` و `viewCount++` و یک رکورد جدید در `viewHistory` با `isReplay = viewCount > 1`.

## نمایش در نوار وضعیت درس (Lesson Status Bar)
زیر عنوان هر درس در صفحه‌ی همان درس، یک خط وضعیت نمایش داده شود، مثلاً:
> «مرور دوباره — مشاهده‌شده در ۱۴۰۴/۰۶/۱۸ با سرعت ۱٫۲۵x» یا «تماشا نشده»

و یک نوار پیشرفت کوچک (Progress bar) که موقعیت seek-jump ها را به‌صورت نقطه‌های کوچک روی نوار زمان نشان دهد (برای دیدن این‌که کاربر کجاها را رد کرده یا پرش زده).

## معماری پیشنهادی روی کدبیس فعلی
- ماژول `shared/feature-playback` را توسعه بده (از قبل در پروژه هست): یک `LessonMediaPlayer` مشترک برای ویدیو (ExoPlayer/Media3) و یک برای صوت با همان ViewModel پایه.
- سینک با `shared/core-sync` و ذخیره‌سازی روی Appwrite Database (کالکشن بالا) + یک Appwrite Function سبک برای merge کردن آپدیت‌های آفلاین هنگام اتصال مجدد (conflict resolution: آخرین `updatedAt` برنده باشد، ولی `viewHistory`/`seekJumps` به‌صورت append، نه overwrite).

## معیار پذیرش
- [ ] بستن و بازکردن اپ، پخش را دقیقاً از ثانیه‌ی قبلی و با همان سرعت ادامه می‌دهد.
- [ ] در دستگاه دوم لاگین‌شده با همان حساب، وضعیت پیشرفت طی چند ثانیه سینک می‌شود.
- [ ] نوار وضعیت درس، تاریخ و سرعت آخرین مشاهده را نشان می‌دهد.
- [ ] پرش‌های seek روی نوار زمان به‌صورت بصری علامت‌گذاری شده‌اند.

# پرامپت: تکمیل ماژول ورزش/یوگا/تنفس + تصاویر مرجع اختصاصی + آموزش نقاشی سیاه‌قلم

> ⚠️ **منسوخ — این نسخه صرفاً جنبه‌ی آرشیوی دارد.** نسخه‌ی نهایی و به‌روز: `پرامپت-02-نسخه-بازنویسی-v2.md`
> (تغییر: زنجیره‌ی سلفی/تولید تصویر با چهره حذف شد؛ تصاویر مرجع استاتیک نهایی شدند؛ ماژولارسازی و جایگاه در منوی دروس اضافه شد.)

## هدف کلی
لیست فعلی حرکات یوگا/ورزشی/تنفسی کم و ناقص است. باید:
1. تعداد و تنوع حرکات زیاد شود (لیست کامل پیشنهادی پایین آمده).
2. هر حرکت مصور شود؛ اما تصویر باید **تولیدی (AI-generated)** و بر اساس یک **عکس مرجع از چهره‌ی کاربر** باشد (کاربر یک سلفی آپلود می‌کند، تصویر حرکت با همان چهره جنریت می‌شود) — نه استفاده از عکس‌های آماده‌ی اینترنتی.
3. یک ایجنت طراح مجزا («ایجنت طراح تصاویر مرجع») اضافه شود که تصاویر مرجع نقاشی سیاه‌قلم (Pencil Sketch Reference) از نیمه‌حرفه‌ای تا حرفه‌ای (سطح ۴ تا ۱۰ از ۱۰) تولید می‌کند.
4. شمارنده‌های تنفس و تکرار حرکات، اعلان صوتی مشخص داشته باشند.

## ۱) ساختار داده‌ی حرکت (Appwrite Collection: `wellness_moves`)
```json
{
  "id": "string",
  "category": "yoga|exercise|breathing",
  "titleFa": "string",
  "level": "1-10",
  "durationSec": "number",
  "reps": "number|null",
  "instructionsFa": "string",
  "audioCueId": "string",       // اعلان صوتی مخصوص این حرکت
  "referenceImagePromptTemplate": "string", // پرامپت پایه‌ی تولید تصویر با چهره‌ی کاربر
  "generatedImageUrl": "string|null"
}
```

## ۲) جریان کار «تولید تصویر با چهره‌ی کاربر»
1. کاربر یک عکس پرتره (سلفی) در تنظیمات پروفایل آپلود می‌کند (با رضایت صریح؛ ذخیره‌سازی فقط برای این منظور).
2. برای هر حرکت، Appwrite Function به نام `generate-move-image` فراخوانی می‌شود که:
   - عکس مرجع کاربر + `referenceImagePromptTemplate` را به سرویس تولید تصویر (image-gen API) می‌فرستد.
   - خروجی را در Storage ذخیره و URL را در `generatedImageUrl` می‌نویسد.
3. تصویر تولیدشده cache می‌شود؛ فقط با تغییر عکس پروفایل یا درخواست صریح کاربر («تولید دوباره») مجدداً ساخته شود.

### نمونه‌ی پرامپت پایه برای هر حرکت (template)
```
یک تصویر آموزشی ساده و واضح از حالت بدنی [نام حرکت]، با چهره‌ای شبیه به تصویر پیوست‌شده (فقط شباهت چهره، نه کپی دقیق)،
در پوشش ورزشی محجبه و مناسب، پس‌زمینه‌ی ساده و روشن، زاویه‌ی دید کامل بدن، سبک illustration آموزشی، بدون متن روی تصویر.
```

- فایل‌های صوتی از قبل ضبط‌شده (TTS فارسی) در Storage نگه‌داری و در `audioCueId` رفرنس شوند؛ پخش هم‌زمان با تایمر بصری روی صفحه.

## ۵) ایجنت طراح تصاویر مرجع سیاه‌قلم (سطح ۴ تا ۱۰)

- کاربر یک سطح مهارت (۴ تا ۱۰ از ۱۰) و یک موضوع (چهره، طبیعت، حیوان، اشیاء) انتخاب می‌کند.
- Appwrite Function به نام `generate-sketch-reference` یک پرامپت تولید تصویر می‌سازد، مثلاً:
```
یک تصویر مرجع برای تمرین نقاشی سیاه‌قلم (پنسیل)، موضوع: [موضوع]، سطح مهارت: [سطح]/۱۰
(سطح ۴ = خطوط ساده و سایه‌زنی پایه؛ سطح ۷ = سایه‌زنی میان‌رده و تناسبات دقیق‌تر؛ سطح ۱۰ = جزئیات حرفه‌ای، نور و سایه‌ی پیچیده، بافت)،
تصویر باید فقط طرح خطی/کدر سیاه و سفید باشد (نه رنگی)، مناسب کپی‌کردن با مداد روی کاغذ.
```
- تصویر تولیدشده در گالری «مرجع‌های من» ذخیره شود؛ امکان درخواست نسخه‌ی جدید با همان موضوع/سطح.

# پرامپت: افزودن قابلیت «درخواست دستور پخت با نام غذا»

## هدف
در بخش آشپزی اپ، کاربر بتواند نام یک غذا را تایپ کند (مثلاً «قورمه‌سبزی» یا «کیک اسفنجی») و دستور پخت کامل دریافت کند.

## رفتار
1. کاربر نام غذا را در یک فیلد جستجو وارد می‌کند.
2. اگر دستور پخت از قبل در دیتابیس محلی (`recipes` collection) موجود باشد → نمایش مستقیم.
3. اگر موجود نباشد → Appwrite Function به نام `generate-recipe` فراخوانی می‌شود که با یک مدل زبانی، دستور پخت را در قالب ساختاریافته تولید می‌کند و در دیتابیس ذخیره می‌کند (برای دفعات بعد کش می‌شود).

## مدل داده (`recipes`)
```json
{
  "nameFa": "string",
  "servings": "number",
  "prepTimeMin": "number",
  "cookTimeMin": "number",
  "ingredients": [{ "name": "string", "amount": "string" }],
  "steps": [{ "order": "number", "text": "string" }],
  "tags": ["ایرانی", "کم‌کالری", "..."],
  "source": "ai-generated|manual",
  "createdAt": "ISO8601"
}
```

## نکات UI
- نمایش با همان کامپوننت "Recipe Card" با امکان تغییر تعداد نفرات (مثل مقیاس‌گذاری خودکار مقادیر مواد اولیه).

# پرامپت: رفع باگ لاگین گوگل، رفع خرابی AI در بخش «همراه»، و افزودن تنظیمات چند-مدل هوش مصنوعی

## بخش ۱ — اصلاح لاگین با گوگل
لاگین با گوگل (Appwrite OAuth2 Google Provider) به‌درستی کار نمی‌کند.

به ایجنت کدنویس بده:
> «کد فعلی لاگین با گوگل در ماژول `feature-pairing`/`core-security` را بررسی کن. موارد زیر را چک و رفع کن:
> ۱. صحت `redirect URI` ثبت‌شده در Google Cloud Console منطبق با URI پروژه‌ی Appwrite باشد.
> ۲. Client ID/Secret گوگل در تنظیمات Appwrite Console درست وارد شده باشد.
> ۳. در Compose، callback موفقیت/شکست OAuth به‌درستی state کاربر را آپدیت کند (فعلاً احتمالاً کاربر بعد از بازگشت از مرورگر در حالت loading گیر می‌کند یا session ست نمی‌شود).
> ۴. Session را بعد از لاگین با `account.get()` مجدداً از سرور بخوان و در `core-common` state ذخیره کن تا کل اپ آن را ببیند.
> خروجی: لاگ خطای دقیق فعلی (اگر در دسترس است) را تحلیل کن و به‌ازای هر علت محتمل، یک تست دستی برای تأیید رفع مشکل ارائه بده.»

## بخش ۲ — رفع خرابی هوش مصنوعی در بخش «همراه» (Pairing/Companion)
بخش «همراه» که با ماژول `feature-pairing` و function `ai-companion` کار می‌کند، رفتار درست AI ندارد.

پرامپت برای ایجنت:
> «در Appwrite Function `ai-companion`، موارد زیر را بررسی کن:
> ۱. آیا کلید API مدل هوش مصنوعی به‌درستی در Environment Variables function ست شده؟
> ۲. آیا پاسخ خطا (rate limit، timeout، فرمت نامعتبر پرامپت) به‌درستی catch و به کلاینت با پیام قابل‌فهم برگردانده می‌شود (نه کرش خاموش)؟
> ۳. آیا context ارسالی به مدل (تاریخچه‌ی مکالمه‌ی همان کاربر با «همراه») به‌درستی از دیتابیس خوانده و به پرامپت افزوده می‌شود؟
> یک لاگ ساختاریافته (request id, userId, promptLength, responseStatus, errorMessage) به این function اضافه کن تا خطاهای بعدی سریع قابل ردیابی باشند.»

## بخش ۳ — افزودن قابلیت «چند مدل هوش مصنوعی + مدیریت کلید API» در تنظیمات
هدف: کاربر (یا ادمین) بتواند از داخل اپ چند مدل/سرویس هوش مصنوعی را تعریف و بین آن‌ها سوییچ کند.

### مدل داده (`ai_providers` — Appwrite Collection، فقط قابل‌مشاهده/ویرایش برای نقش ادمین)
```json
{
  "id": "string",
  "providerName": "string",     // مثلا "OpenAI", "Claude", "Gemini", "Local-LLM"
  "apiKeyEncrypted": "string",  // با core-security رمزنگاری شود، هرگز plain-text ذخیره نشود
  "modelId": "string",          // مثلا gpt-4o-mini، claude-sonnet
  "endpointUrl": "string",
  "isActive": "boolean",
  "usedFor": ["lesson-ai-engine", "ai-companion", "generate-recipe", "generate-move-image", "generate-sketch-reference"],
  "createdAt": "ISO8601"
}
```

### الزامات
- صفحه‌ی تنظیمات جدید: «مدل‌های هوش مصنوعی» با فرم افزودن/ویرایش/حذف provider.
- کلید API هرگز در کلاینت لاگ یا نمایش کامل نشود (فقط ۴ رقم آخر نمایش داده شود).
- هر Appwrite Function (lesson-ai-engine، ai-companion، generate-recipe، ...) باید به‌جای کلید هاردکد، از این کالکشن provider فعال مربوط به خودش را بخواند؛ اگر provider فعال fail شد، به provider بعدیِ فهرست fallback کند (retry با مدل جایگزین).
- لاگ مصرف (تعداد فراخوانی هرماه به تفکیک provider) برای کنترل هزینه.

## معیار پذیرش
- [ ] لاگین گوگل بدون گیرکردن در حالت loading کامل می‌شود و session پایدار می‌ماند.
- [ ] بخش «همراه» خطاهای AI را با پیام قابل‌فهم نشان می‌دهد، نه سکوت/کرش.
- [ ] از تنظیمات می‌توان حداقل دو provider هوش مصنوعی اضافه و بین آن‌ها سوییچ کرد؛ کلید API رمزنگاری‌شده ذخیره می‌شود.

# پرامپت: قالب استاندارد برای افزودن/بروزرسانی هر درس در آینده (همه‌ی کتاب‌ها)

هدف این فایل این است که هر بار درس/کتاب جدیدی آماده شد (سال بعد، یا اصلاح محتوای فعلی)، همان قالب یکسان به سرور اضافه شود بدون نیاز به طراحی مجدد ساختار.

## قالب پوشه‌بندی استاندارد هر کتاب و هر درس (سمت محتوا/آپلود)
```
[شماره] - [نام کتاب/درس] (کد کتاب)/
  cover_[کد کتاب].jpg                 → فقط کاور رسمی کتاب؛ تصاویر داخلی در این سطح قرار نگیرند
  [فصل/بخش در صورت وجود]/
    [شناسه درس] - [عنوان درس]/
      [کد کتاب]_[شناسه درس]_BOOK.pdf  → PDF کتاب/درس مربوط
      00-تصاویر/                       → تمام تصاویر داخلی مورد استفاده در فایل‌های HTML همین درس
      01-جزوه_راهنما/                  → HTML/محتوای جزوه و راهنما
      02-نکات_کلیدی/                   → نکات فشرده برای مرور سریع
      03-فلش_کارت/                     → فایل فلش‌کارت (JSON یا HTML قابل‌پارس)
      04-سوالات/                       → بانک سوال
      05-پاسخ_سوالات/                  → کلید سوالات بالا
      06-پاسخ_تمرین_کتاب/              → (اختیاری) حل تمرین‌های خود کتاب درسی
```

### استاندارد مسیر و نام‌گذاری فایل‌های HTML و تصاویر
- هر فایل HTML باید در پوشه محتوای خودش قرار داشته باشد و نام آن با **کد کتاب + شناسه درس + عنوان محتوای اختصاری** ساخته شود تا در کل پروژه یکتا و قابل شناسایی باشد.
- الگوی نام HTML:
  `[کد کتاب]_[شناسه درس]_[عنوان-اختصاری-محتوا].html`
- نمونه‌ها:
  `C905_E01-L01_JOZVE-RAHNAMA.html`
  `C905_E01-L01_NOKAT-KELIDI.html`
  `C905_E01-L01_SOALAT.html`
  `C905_E01-L01_PASOKH-SOALAT.html`
  `C905_E01-L01_PASOKH-TAMRIN.html`
- هر تصویر داخلی باید فقط در `00-تصاویر` همان درس قرار گیرد و نام آن نیز باید شامل **کد کتاب + شناسه درس + عنوان اختصاری محتوایی که تصویر به آن تعلق دارد + شماره یکتا** باشد.
- الگوی نام تصویر:
  `[کد کتاب]_[شناسه درس]_[عنوان-اختصاری-محتوا]_IMG[شماره].ext`
- نمونه:
  `C905_E01-L01_JOZVE-RAHNAMA_IMG01.webp`
  `C905_E01-L01_SOALAT_IMG01.webp`
  `C905_E01-L01_NOKAT-KELIDI_IMG01.webp`
- این الگو برای جلوگیری از برخورد نام فایل‌ها در کل پروژه الزامی است؛ شماره تصویر باید در محدوده همان درس/محتوا یکتا باشد.
- در تمام HTMLهایی که در پوشه‌های محتوایی درس قرار دارند، مسیر تصویر باید **یک پوشه به عقب و سپس داخل `00-تصاویر` همان درس** باشد:
  `../00-تصاویر/[نام فایل تصویر]`
- بنابراین تصاویر داخلی نباید با مسیرهای قدیمی، مسیر مطلق، یا مسیر وابسته به ریشه پروژه در HTML ارجاع داده شوند.
- **کاور رسمی کتاب استثناست:** کاور در ریشه پوشه کتاب با نام `cover_[کد کتاب].jpg` باقی می‌ماند و در قانون تصاویر داخلی `00-تصاویر` قرار نمی‌گیرد.
- همه تصاویر داخلی موجود در ساختار قدیمی، به‌جز کاورهای رسمی، باید حذف شوند و در صورت نیاز فقط تصاویر مورد استفاده توسط HTML با استاندارد نام‌گذاری بالا در `00-تصاویر` قرار گیرند.

## قالب رکورد درس در Appwrite (Collection: `lessons`)
```json
{
  "bookCode": "string",
  "bookTitleFa": "string",
  "subjectOrder": "number",
  "lessonNumber": "number",
  "lessonTitleFa": "string",
  "prerequisiteSummaryId": "string|null",  // لینک به ماژول پیش‌نیاز (فایل ۰۶)
  "hasVideo": "boolean",
  "hasAudio": "boolean",
  "flashcardSetId": "string|null",
  "questionBankId": "string|null",
  "examRangeGroup": "string"   // برای گروه‌بندی آزمون‌های بازه‌ای
}
```

## پرامپت آماده برای ایجنت هنگام افزودن درس جدید
> «یک درس/کتاب جدید طبق قالب پوشه‌بندی استاندارد بالا دریافت شده است. لطفاً:
> ۱. محتوای هر زیرپوشه را به کالکشن‌های مربوطه‌ی Appwrite (`lessons`, `flashcards`, `question_bank`, `lesson_media_progress` schema) وارد (seed) کن — از اسکریپت موجود `backend/seed/import.js` به‌عنوان الگو استفاده کن و مسیرهای محتوای جدید را مطابق ساختار واقعی پوشه‌های هر درس پردازش کن.
> ۲. اگر فایل ویدیو/صوت وجود دارد، رکورد اولیه در `lesson_media_progress` برای هر کاربر لازم نیست ساخته شود (Lazy — فقط هنگام اولین پخش ساخته شود).
> ۳. اگر پیش‌نیاز (نکات سال قبل) داده نشده، از الگوی ماژول پیش‌نیاز (فایل ۰۶ همین بسته) یک رکورد خالی برای تکمیل دستی بساز.
> ۴. تست کن که درس جدید در منوی همان کتاب/همان ترتیب ظاهر شود.»

## معیار پذیرش
- [ ] افزودن یک درس جدید فقط با رعایت پوشه‌بندی بالا و اجرای اسکریپت seed، بدون تغییر کد UI انجام می‌شود.

# پرامپت: ماژول مجزای «پیش‌نیاز و جمع‌بندی» در ابتدای هر درس

## هدف
قبل از شروع محتوای اصلی هر درس، یک بخش مجزا (ماژول جداگانه، نه فقط یک پاراگراف) با نکات ضروری و پیش‌نیاز از سال‌های قبل نمایش داده شود؛ چون کاربر (زهرا) وارد پایه نهم شده و ممکن است نکات پایه فراموش‌شده باشد.

## محتوای این ماژول به تفکیک درس
| درس | نوع محتوای پیش‌نیاز |
|---|---|
| ریاضی | فرمول‌های ضروری سال‌های قبل (اتحادها، رادیکال، درصد، تناسب)، فلش‌کارت فرمول |
| عربی | گرامر پایه (فعل ماضی/مضارع، اعراب ساده)، فلش‌کارت واژگان پرتکرار |
| انگلیسی | گرامر پایه (Tenses ساده، افعال کمکی)، فلش‌کارت واژگان |
| علوم | مفاهیم پایه‌ی مورد نیاز فصل جدید (مثلاً پیش از فصل شیمی، یادآوری اتم/مولکول از سال قبل) |
| فارسی/نگارش | یادآوری آرایه‌های ادبی و نکات دستوری پایه |
| سایر دروس | چکیده‌ی نکات مهم فصل مرتبط سال قبل (در صورت وجود) |

## مدل داده (`lesson_prerequisites`)
```json
{
  "lessonId": "string",
  "type": "formula|grammar|vocabulary|concept",
  "titleFa": "string",
  "contentFa": "string",
  "flashcardSetId": "string|null"
}
```

## رفتار UI
- در صفحه‌ی هر درس، بالای محتوای اصلی، یک کارت/آکاردئون با عنوان «قبل از شروع، این نکات را مرور کن» قرار گیرد.
- اگر `flashcardSetId` دارد، دکمه‌ی «مرور فلش‌کارت پیش‌نیاز» زیر آن باشد.
- این بخش قابل جمع‌شدن (collapse) است اما پیش‌فرض باز باشد تا دیده شود، و وضعیت "دیده‌شد/نادیده گرفته شد" هم مثل پلیر رسانه، در پروفایل ذخیره شود (برای گزارش پیشرفت والدین/معلم).

## پرامپت آماده برای ایجنت
> «برای هر درس در `lessons` collection، یک بخش پیش‌نیاز طبق مدل `lesson_prerequisites` بساز و در نمای Compose صفحه‌ی درس، بالای محتوای اصلی، به‌صورت کارت آکاردئونی نمایش بده. محتوای اولیه را برای دروس ریاضی، عربی، انگلیسی و علوم (که بیشترین وابستگی به سال قبل را دارند) از روی فایل‌های HTML موجود در پوشه‌های `01-جزوه_راهنما` و `02-نکات_کلیدی` هر درس در ساختار محتوای پایه نهم استخراج/خلاصه کن.»

## معیار پذیرش
- [ ] هر درس با پیش‌نیاز فعال، کارت جمع‌بندی را قبل از محتوای اصلی نشان می‌دهد.
- [ ] دیدن/ندیدن این کارت در پروفایل پیشرفت ثبت می‌شود.

# پرامپت: ماژول آزمون بازه‌ای، اصلاح خودکار، بازخورد، و برنامه‌ریزی هفتگی بر اساس برنامه‌ی کلاسی/شیفت چرخشی

## بخش ۱ — آزمون‌گیری بر اساس بازه‌ی درسی
هر کتاب به بازه‌های درسی (مثلاً فصل‌ها یا هر ۳-۴ درس) تقسیم شود و در پایان هر بازه یک آزمون کوتاه تولید شود.

### مدل داده
```json
{
  "examId": "string",
  "bookCode": "string",
  "rangeGroup": "string",        // همان examRangeGroup در فایل ۰۵
  "questions": [{ "questionId": "string", "type": "mcq|short_answer", "weight": "number" }],
  "assignedAt": "ISO8601",
  "dueAt": "ISO8601|null"
}
```
```json
// نتیجه‌ی آزمون هر کاربر
{
  "examId": "string",
  "userId": "string",
  "answers": [{ "questionId": "string", "givenAnswer": "string", "isCorrect": "boolean" }],
  "score": "number",
  "weakTopics": ["string"],     // موضوعاتی که غلط پاسخ داده شده
  "takenAt": "ISO8601"
}
```

## بخش ۲ — اصلاح خودکار و بازخورد
- سوالات چندگزینه‌ای: اصلاح فوری و محلی.
- سوالات تشریحی کوتاه: با همان Appwrite Function AI (از فایل ۰۴، از provider فعال) ارزیابی و نمره‌دهی تقریبی + بازخورد متنی کوتاه شود.
- بعد از هر آزمون: صفحه‌ی «نکات ضعف» نمایش داده شود که فقط `weakTopics` را با لینک مستقیم به همان نکته‌ی کلیدی/فلش‌کارت مرتبط نشان دهد (نه کل درس دوباره).

## بخش ۳ — برنامه‌ریزی هفتگی بر اساس برنامه‌ی کلاسی و شیفت چرخشی
اپ باید بتواند برنامه‌ی هفتگی مرور را بر اساس: (الف) برنامه‌ی کلاسی هفتگی زهرا (کدام درس کدام روز کلاس دارد)، (ب) شیفت چرخشی (اگر برنامه‌ی هفتگی هر هفته یا هر چند هفته جابه‌جا می‌شود)، خودکار بچیند.

### مدل داده (`weekly_schedule`)
```json
{
  "cycleWeekIndex": "number",     // برای شیفت چرخشی: کدام هفته از چرخه
  "dayOfWeek": "string",
  "classSlots": [{ "bookCode": "string", "startTime": "string", "endTime": "string" }]
}
```
```json
// برنامه‌ی مرور تولیدشده
{
  "userId": "string",
  "date": "ISO8601",
  "reviewTasks": [
    { "bookCode": "string", "type": "flashcard|video|exam|prerequisite", "refId": "string", "isDone": "boolean" }
  ]
}
```

### منطق تولید برنامه‌ی مرور (پرامپت برای Appwrite Function `weekly-plan-engine`)
> «با توجه به `weekly_schedule` (شامل `cycleWeekIndex` برای شیفت چرخشی) و تاریخ امروز:
> ۱. مشخص کن امروز کدام هفته از چرخه است و امروز چه دروسی کلاس دارند.
> ۲. برای هر درسی که «فردا» کلاس دارد، یک تسک مرور فلش‌کارت + نکات کلیدی همان درس برای «امشب» بساز.
> ۳. برای دروسی که در ۷ روز اخیر آزمون بازه‌ای داشته‌اند و `weakTopics` دارند، یک تسک مرور نقطه‌ضعف اضافه کن.
> ۴. اگر امروز روز آزادی از کلاس‌هاست، یک تسک «مرور آزاد» برای پرتکرارترین دروسِ ضعیف بگذار.
> خروجی JSON را در `weekly_schedule/review_tasks` بنویس و به کاربر (و در صورت فعال بودن، والدین از طریق `notify-guardian`) اعلان بفرست.»

## معیار پذیرش
